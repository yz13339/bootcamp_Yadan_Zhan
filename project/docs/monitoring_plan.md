# Monitoring plan

The deployed classifier supports weekly risk review and requires monitoring across four layers. **Data:** schema drift or missing prices could invalidate features; alert the data analyst when required-column checks fail, null rate exceeds 1%, or the latest market date is more than two business days old. First action: stop scoring and compare the source extract with Yahoo Finance. **Model:** regime change can degrade discrimination; alert the model owner when four-week recall for high-stress days falls below 0.50, prediction-positive rate changes by more than 10 percentage points, or feature PSI exceeds 0.10. First action: reproduce the window and compare with the prior model.

**System:** API or pipeline failure can delay the review. Platform on-call receives alerts when daily job success falls below 99%, p95 API latency exceeds 500 ms, or HTTP 5xx exceeds 1% over 15 minutes. First action: inspect application and pipeline logs, then roll back to the last model bundle. **Business:** the portfolio manager is alerted if high-stress alerts exceed 40% of days in a month or a realized stress day is missed twice in four weeks; the first action is human review, not automatic trading.

Retrain quarterly, or earlier after recall/PSI breaches persist for two windows. The risk analyst owns data dashboards and weekly review; the model owner validates retraining; platform on-call operates the service; the portfolio manager approves model promotion or rollback. Issues and decisions are logged in the repository issue tracker with model version and affected dates.
